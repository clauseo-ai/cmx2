# decisions

locked unless the maintainer says otherwise. the reasoning for each is in its row.

terms: pi is the open source agent engine cmx2 builds on; boxbox is the web client (https://github.com/clauseo-ai/boxbox2); the contract is the daemon's http api; cmx is the predecessor (https://github.com/clauseo-ai/codemaxxxing).

| # | decision | status |
|---|---|---|
| D1 | **base: pi** (`earendil-works/pi` 0.99.1, MIT) as the engine; cmx2 is the runtime around it. not a fork of pi: pi is a dependency, our code is extensions plus our own packages. | locked |
| D2 | codex cli, goose, opencode v2, claude agent sdk are **design references**, not bases. | locked |
| D3 | **everything on day one.** the full feature list is the definition of done; no v1 with gaps. | locked |
| D4 | **the bitter lesson** governs prompts and harness rules: primitives, guardrails, measurement; the model decides. | locked |
| D5 | **effort policy**: seat and dispatch defaults; a turn-level dial via per-message effort; upward-only escalation on failure signals at boundaries. no model-callable "lower my effort"; no top-level effort changes mid-conversation; no thinking-mode toggles mid-turn. escalation stops at a per-model ceiling (`escalation.ceiling`: opus 5.5 and fable 5.1 at xhigh, sonnet 5.5 at high, max otherwise), because on code opus 5.5 at max scores below xhigh for more money and sonnet 5.5 past high loses to a cheaper opus run (benchmarked 2026-10-01). escalation never changes the model: a sonnet 5.5 turn at its ceiling stays sonnet at high. a hand-off to opus 5.5 at high was weighed and refused (maintainer, 2026-10-03): the prompt cache is per model, so every hand-off would re-read the whole transcript uncached; putting work on opus is the driver's call, made by spawning on an opus seat. | locked |
| D6 | **routing**: seats not models; presets `opus-led` (the default) and `fable-led`; sonnet 5.5 as the engineer seat in opus-led; scout sonnet 5.5 medium; reviewer on a different model than the author; bulk sonnet 5.5, gemini only when a job needs it; efforts a model never runs at come from the `never` list in config alone, shipped empty. the built-in floors (opus 5.5 never xhigh, sonnet 5.5 never max) stood on a legal benchmark with a step-cap confound and were dropped once on code opus 5.5 xhigh measured at or above high (benchmarked 2026-10-01). routing lives in `routing.jsonc`, hot-reloaded, not in agents.md prose. | locked; presets tunable |
| D7 | **subagent surface**: five verbs (`spawn`, `message`, `wait`, `agents`, `run`); supervision and pools as spawn options; links removed; done = parked; children never self-close; caps count running turns. | locked |
| D8 | **the root parks** when only children or jobs remain; steer admission replaces flush. | locked |
| D9 | **processes** are session-owned, ledgered each turn, reaped at session end unless `keep`ed; background jobs notify into the mailbox; nobody polls. | locked |
| D10 | **worktrees** are plain tools (create/merge/discard) with env and `.env*` carried and an apfs copy-on-write fast path; the review card is opt-in. | locked |
| D11 | **dropped**: plan mode and its tools, wave runner and agents, caveman agent, todo tools on 5.x models, hono/httpapi dual backends, `task`/`bash` names, porting the afterglow tui renderer. | locked |
| D12 | **tui**: pi's tui, themed; boxbox is the main surface. | locked |

| D14 | **compaction** requests reuse the session prefix; background prefire; degenerate rejection; notes file across windows; recall kept. | locked |
| D15 | **memory budget** is a test: idle < 150 MB, three active 300k sessions < 400 MB. | locked |
| D16 | **pi is pinned exactly**; upgrades are a deliberate step with the changelog read and the drift tests run; we never patch pi source. | locked |
| D17 | **licenses**: borrow only from repos with a LICENSE file; ask `aliou/pi-processes` and `nicobailon/pi-interactive-shell` before copying. | locked |
| D18 | **runtime**: bun for our packages (single binary, `bun test`); pi is node-first and bun-clean, hosted in-process. | locked |
| D20 | **open source, MIT, from the first commit**; nothing machine- or user-specific in code or prompts; one binary per platform; `serve --install`, `pair`, `doctor` for fleet setup (a fleet is the set of machines each running a daemon); boxbox pairs by url + one-time token; the contract ships as a package. | locked |
| D21 | **streams are served by `node:http` behind a tcp front, not by `Bun.serve`.** the public port splits: websocket upgrades to an internal `Bun.serve`, everything else to `node:http`. beat: staying on `Bun.serve` (no backpressure on streaming responses in bun 1.3.14: a stalled subscriber grew the daemon to 2.8 GB in 4 s, so the 1 MB per-subscriber cap could not be enforced); a websocket library on `node:http` (bun's `node:http` cannot serve upgrades). cost: one loopback hop per request. revisit when bun ships response backpressure; the drift test pins the bun version the measurement was made on. | m6a, measured (`GOTCHAS.md`, "sync and the listener") |
| D22 | **escalation is per turn and comes back down, and the main session never escalates.** supersedes D5's "upward-only" for helpers; D5 stays locked as written. a helper's failure signals (the same tool error twice, the same check failing twice after an edit, the output cut at the token limit, the same call three times, except `wait` and `agents`) raise its next turn one allowed rung; the first later turn without signals puts the effort back at the session's baseline (the dial, or the stored effort at open). the raise is never stored: `session.effort` and the session row only ever carry the baseline, and `session.escalated` / `session.deescalated` announce the moves. the main session's model and effort are the user's dial, so roots pass no `escalate` hook at all. why: in one long build the root ran nearly every step at max after one escalation 20 minutes in on "the same wait call three times", and a failing test after an edit (the normal red-green loop) escalated on its first failure. D5's "no model-callable lower my effort" still holds: the harness lowers, the model never does (maintainer, 2026-10-09). | decided |
| D23 | **Q6 resolved: the prompt-cache ttl follows the session's waits, switched once.** a session without an explicit `cache_ttl` marks its requests 5m until it has a helper that is not closed, a background job that will notify it, or a last step whose context passed 100k tokens; from then on 1h, for the life of the session (an explicit `cache_ttl` on `POST /session` or `spawn` is never overridden); the switch is stored on the session row (`cache_ttl: "1h"`), so eviction and restart keep it. measured 2026-10-09 through a vertex endpoint: a request marked 1h does not read an entry written at 5m (opus 5.5 0 of 10 against 7 of 10 for 5m then 5m; sonnet 5.5 1 of 10 against 10 of 10), and the reverse does not either, so the switch costs one rewrite of the prefix at 2× input and the monotonic rule bounds it to one. why: in one long build most of the root's cost was cache rewrites after waits of 5 to 60 minutes. the answer is read once per request so one request never mixes ttls (the api refuses a 1h block after a 5m one) (maintainer, 2026-10-09). | decided |
| D24 | **routing is a table of models and a guide; seats and presets are gone.** supersedes D6 (locked as written) and the seat half of D5's "seat and dispatch defaults". `routing.jsonc` version 2 holds `models` (alias → `provider/model-id`, a default effort and a one-line note the delegating model reads), a `guide` (where to start and where to step up for each kind of task) and `rules`, plus the unchanged `never`, `caps` and `escalation`. a spawn names a model (`spawn(model: "sonnet")`); it must say which one unless the agent type names its own, because every spawn is a cost decision and a silent default hides it. rest keeps accepting a `provider/model-id`, and a rest body that sends `seat` is refused (`SeatsRemovedError`). the guide and rules are defaults the model reads, not limits (D4): the harness enforces only `never`, `caps` and the escalation ceilings. the alias is the helper's label (session title `name (alias)`, the roster's `seat` field). a version-1 file still loads, its seat keys ignored with one warning; shared keys keep working. `review` joins `explore` as a built-in agent type (reads, searches and runs commands, no write, edit or worktree tools). stepping up is a spawn with `after`, which attaches the earlier helper's brief and last report and writes a `step_up` metric. haiku 5.5 joins the table, and the shipped `never` keeps it off xhigh and max (an xhigh turn can end with no visible text, and a helper's final text is its report). the table is a hypothesis built from benchmarks and others' practice, and stays one until the routing eval (`VERIFICATION.md`, "the routing eval") measures it on real work. contract version 7. | decided 2026-10-09; locked once the routing eval agrees |
| D25 | **a ready summary is used at the first cold cache, and kept fresh as the tail grows.** adds to D14 (locked as written). under the threshold, a request whose prompt cache is cold (more than the ttl plus 30 s since this session last read or wrote it, through a turn, a warm refresh or a summary request, or the model changed since) compacts when a prefire summary is ready: the request rewrites the cache anyway, and the summary makes that rewrite the summary and its tail instead of the whole context. it uses only the ready summary; one asked for then would itself pay the rewrite, so a stale one means no compaction. `session.compacted` says `cold: true` and the record carries `cold`; the trigger stays `auto`. a ready summary whose following messages pass max(`keep` × `at`, 20k tokens) is refreshed in the background over the current messages; the old one stays in use until the refresh lands, a compaction or revert in between drops the refresh, and a failed refresh is not retried before the next compaction. why: a long session whose summary was made at 85% of `at` idled past the 1h ttl three times before reaching `at`, and each return rewrote nearly the whole context at the cache-write rate, over half of that window's cost; and a summary made once at the prefire line let the verbatim tail grow to half of `at`. warming (`warm`) keeps a parked session's cache from going cold, so a warmed session does not take this path. | decided 2026-10-12 |
| D26 | **past the cold floor, an idle session summarises while warm and compacts at its first cold request.** adds to D25. `compaction.cold` (200k tokens by default, a fraction of the window when at most 1, false for D25 alone) is a floor: a turn that settles at or past it schedules a summary at 90% of the cache ttl after the last cache use. when the timer fires and the session is still idle and its cache unexpired, the summary is made from the cache (first, or the refresh when the ready one's tail passed the refresh line); nothing compacts then, and the request counts as cache use, so a return within the next ttl goes on warm with the summary kept. the first request whose cache is cold at or past the floor compacts: from the ready summary, or from one made then with no cache marks (it writes nothing; its prefix is about to go). under the floor D25 holds. a session waiting on its idle summary stays loaded like a warming one; a disposed one (closed, ended, evicted) cancels it. an evicted session leaves its ready summary and last cache use in memory (64 sessions at most) for its next load; after a restart the last reply's time stands in for the last cache use. why: a summary made from a warm cache reads the context at a tenth of the input price, where a return after the expiry rewrites all of it; at 300k the warm summary costs about a sixth of a cold one, so it pays once more than about one in six idle threads comes back, and long threads come back far more often than that. closed helpers never come back, so they pay nothing. | decided 2026-10-14 |
| D27 | **a helper is not told its model or effort; the spawner's reasoning for the model choice goes in `why`, never the brief.** the first message names the helper, its path and its spawner and nothing about what it runs on. a stated effort invites the model to scale its work to the label, and escalation can change the effort mid-session, so the label goes stale. `spawn` takes an optional `why` (one line), which is stored in the agent's options, shown in `AgentInfo` and by the `agents` tool (there only on agents below the caller, so a helper never reads its own), written to the `step_up` and `retry` metrics, and never put in the envelope, the attachments or the notes. (maintainer, 2026-10-18) | decided |
| D28 | **a cache refresh hangs up at message_start; roots are warmed; helpers keep the 5m ttl.** adds to the warming in D25 and the ttl rule in D23. (1) a refresh re-sends the last request byte for byte and aborts on the raw anthropic `message_start` (pi's `onProviderStreamEvent`), taking usage and cost from it; after that abort, an aborted or failed end of the stream is a success. providers that send no `message_start` abort at the first event carrying usage, as before. measured through a vertex endpoint: a request cut at `message_start` is logged as 499 cancelled with 0 to 25 output tokens, and the rest of the reply is not counted; but pi records usage on `message_start` without pushing an event, so the first event cmx2 saw was the first content block, which can follow seconds of thinking, and a refresh sometimes paid hundreds of output tokens. anthropic's `max_tokens: 0` pre-warm is not used: vertex refuses it streamed, and unstreamed it produced no output but wrote the prefix again instead of reading the live entry (2 of 2). (2) the engine's `warm` option is asked with the ttl in force. (3) a root is warmed while parked: 4 hours on the 1h ttl, since a refresh every 54 minutes costs a cache read, about a fortieth of the rewrite a return after an hour pays; 20 minutes on the 5m ttl, since refreshes every 4.5 minutes would cost more than that rewrite over hours. a session with no agent row and no parent counts as a root (root rows are made on first need). helpers keep 20 minutes. the residency cap still holds: warming roots count toward MAX_RESIDENT, and past it the oldest root whose warming is only timers is evicted (never one with a refresh, summary or btw on the wire); it stops warming and its next return pays a rewrite. warming helpers are never evicted, and the idle sweep evicts no warming session. (4) the 100k context reason for the 1h ttl applies only to sessions with no parent: helpers rarely wait more than 5 minutes between steps, a parked helper is warmed at 5m, and the switch rewrites the whole prefix at twice the input price. refresh spend is kept in `cache_refresh` and the session totals. | decided 2026-10-22 |
